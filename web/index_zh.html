公開概覽

透過物理模型,加速 AI 建構物理世界經驗與訓練。

Meadow 是一套以物理為基底的學習模式。工程師只需輸入機器人的規格描述與目標,系統將在 3 分鐘*[註] 內產生可部署的反應策略,以及可即時校正的自監督流水線。

當真實世界發生漂移——摩擦、負載、感測器偏移、磨損——具名變數校正迴圈會指出哪一個物理參數發生變化,並在本地重新蒸餾。不需要重新收集示範,也不需要整個策略重訓。

[註] 依任務複雜度而定:Cube scorer ~25 秒、TwoRoom scorer ~48 秒、PushT 含反應策略蒸餾 ~168 秒。皆在單一 Apple M1 Max + MLX 上實測。詳見「已驗證數字」表。

問題

每一個客製化機器人的部署,都要花兩週的工程時間。

  1. 示範資料的成本

    Diffusion Policy 每個任務需要數百筆遙控示範;VLA pipeline 需要數百萬筆。每次更換 fixture 或 SKU 都要從頭收集。每一次改動,都是數週的時間。

  2. 人工微調

    當摩擦、負載或感測器偏移發生變化,操作員必須打開控制器、肉眼判讀軌跡、手動調整參數。每一次漂移事件,就是數小時的高成本人力。

  3. 黑盒漂移

    端到端學習的策略無法告訴你「是什麼變了」。診斷只剩下「概念漂移」這個籠統的詞。重新收集示範、重新訓練、重新部署——這個循環永遠無法變便宜。

兩週時間都花在哪?

客製化機器人部署的兩週工程,業界主流路線(Diffusion Policy / VLA / 傳統 PLC)的典型分配如下。

階段 建構內容 對應設備 / 工具
Day 1–3 規格定義 + teleoperation 示範資料收集(每任務通常需數百筆 demo) Teleop rig(ALOHA / Mobile ALOHA / Meta Quest 主從手臂)· 真實 robot · 操作員 1–2 人
Day 3–7 資料清洗、標註、模擬器建模、failure case 補錄 工程師 workstation · 雲端儲存 · 模擬器(MuJoCo / Isaac Gym)
Day 7–12 Policy 訓練(Diffusion Policy / VLA / RL)、超參數搜尋、回測 Cloud GPU(A100 / H100,~$5–$50 per cycle)· ML 工程師 · 訓練 framework(PyTorch / JAX)
Day 12–14 Sim2real 校正、手動調參、integration test、文件交付 真實 robot · operator · 控制器(Siemens / Rockwell / 自家 PLC)

時程為業界典型範圍——整理自 Diffusion Policy、ALOHA / Mobile ALOHA、Physical Intelligence π0 等公開資料。實際時程依任務複雜度差異從一週到數週不等;若是 VLA 等大型 foundation policy,僅資料收集就可能耗時數週至數月。

工業機器人市場大約 $200B。大部分都被這個工程瓶頸卡住。Meadow 直接攻這個瓶頸。

取徑

為「部署面」而設計,不是為了排行榜。

三項設計承諾——刻意停在「我們做到什麼」(What),而不是「我們怎麼做」(How)。讓這些成果能夠成立的具體架構,我們選擇在正確的脈絡下與適合的對象直接交流,而不是公開發表。

  1. 輸入是具型別與具名的

    系統接受一份結構化、具名的描述——關於機器人、場景與目標——而不是原始影片串流。好處是:每一個驅動行為的變數都有一個工程師能指認的名字。這是讓接下來兩項承諾得以成立的前提。

  2. 可部署的成品又小又快

    最終策略大小落在 0.077–2.04 MB,在消費級 Apple Silicon 上每次決策 0.095–0.122 ms。這是不可妥協的限制:如果無法塞進客戶的筆電,並在真實控制迴圈中即時回應,我們就不會稱之為「已部署」。

  3. 漂移是具名的,不是黑盒

    當部署中的策略開始在真實世界失準,系統會定位出哪一個物理參數偏離了原本的假設——摩擦、負載、感測器偏移、接觸剛度——並只在本地修正這一個量,而不是重訓整個策略。這是大多數既有方法尚未提供的能力,也是客戶能在不送資料上雲端的前提下完成重新校正的關鍵。

這些成果——分鐘以內的訓練、毫秒以內的推論、具名變數校正——可以從本頁的公開 artefact 與影片中直接驗證。讓這些成果得以成立的具體 pipeline,我們選擇先保留;若您希望更深入評估,歡迎直接聯絡。

切入市場

半導體設備校正——最痛、付費意願最高。

單一台 EUV 微影機台造價 $200M 以上。一小時非計畫停機就燒掉數十萬美元。Operator 目前診斷 chamber drift 的方式是讀感測器 log、調整參數、重跑 test wafer——通常每次漂移事件需要 4 小時。

Fab 本來就追蹤具名物理參數:chamber pressure、laser drift、alignment offset。Meadow 的 spec-driven 校正迴圈直接 map 到他們既有的資料結構,不需要 paradigm 級別的改變。

創辦人在台灣,離各大 fab 與 tier-1 設備供應商一小時車程內——這是海外競爭者在早期客戶探索與 pilot 階段沒有的物理存取優勢。本公開文件不點名具體買家。

量化價值:60 秒筆電時間取代 4 小時 operator 分析——每一次漂移事件,operator 生產力提升大約兩個數量級。關鍵是,所有校正都在工程師本地筆電上完成;wafer 與專有資料不離開 fab perimeter——這移除了 IT security review 的一個真實採購阻礙。

Beachhead:在 wedge 垂直市場找 design partners。延伸:工業機器人整合商、自駕場景測試、手術機器人——同樣的 approach 在第一個垂直站穩後即可一般化。

常見問題

七個問題,直接回答。

研究者、投資人、合作夥伴常問的問題——以適合公開文件的細節層次回答。更深入的細節會在個別對話中分享。

Q1

Meadow 在做什麼?

Meadow 把客製化機器人部署從「數週的示範收集 + 工程師調參」轉換為「5 分鐘的規格更動」。工程師用具型別、具名的規格描述機器人與目標;系統產生可部署、毫秒級延遲的反應策略,在客戶本地硬體上運作。當真實世界發生漂移,系統會定位哪一個物理參數偏離了原假設,並只在本地修正,不需要重訓整個策略。

Q2

為什麼是這個團隊?

黃聖凱(Sheng-Kai Huang)。物理與 ML 系統背景。多年在「資料驅動預測」與「因果物理推理」這條邊界上工作——這正是 Meadow 所要解決的核心 gap。

單人完成並 ship 四個已驗證的展示任務,加上一條 pipeline 跑通四個標準化 benchmark family,所有 artefact 皆可重現。熟悉 device-side Apple Silicon ML 堆疊與相關模擬工具。

現階段刻意維持單人 founder:迭代快、決策一致。在策略契合的前提下,歡迎引進強的商業 co-founder。

Q3

取徑特別在哪?

  • 物理優先的輸入。系統從具名物理狀態開始,而不是像素——這跟生物智能的起點一致(在視覺成熟之前的前庭、本體感覺、接觸訊號)。
  • 消費級筆電上的分鐘以內訓練。Apple Silicon 上 60 秒以內完成訓練——無 discrete GPU、無雲端。現場工程師可以在自己的機器上、用一杯咖啡的時間完成重新校正。
  • 具名變數校正。當部署的策略發生漂移,我們指出哪一個物理參數偏離了——不是模糊的 concept drift——並在本地只修正那一個量。
  • 把可重現視為一級特性。本文件每一個數字都可以從本頁的公開 artefact 驗證;這個透明度在當前領域中是少見的(見 Figure 5)。
Q4

進度到哪?

產品(v0.0.2 已 ship,所有實驗在單一 Apple M1 Max + MLX 上完成):

  • 4 個展示任務,皆有持久化 artefact(TwoRoom、PushT、Reacher、OGBench Cube)
  • 4 個 OGBench v1 family 用同一條 pipeline 通過(每個 8/8、443–2,724 samples / family)
  • PushT 上達到次像素反應精度(最終 block 誤差 0.81 px)
  • 反應推論延遲 0.095–0.122 ms(Core ML;對 < 2 MB 的 policy,CPU+GPU 為 benchmark 最佳組合)
  • 可部署的 artefact 大小 0.077–2.04 MB
  • 評分網路訓練 wall-clock:~48 秒(TwoRoom, 1,799 iter)· ~25 秒(Cube, 1,399 iter)——消費級 M1 Max,無雲端 GPU
  • 反應策略蒸餾 wall-clock:~112 秒(PushT student v10)在同一台機器上

客戶端:pre-revenue。半導體設備工程師客戶探索訪談進行中。目標:第一個付費 pilot 在六個月內。

資金:bootstrap,目前無外部投資。

Q5

還有誰在做類似的事?

  • Diffusion Policy(Columbia / Toyota):visuomotor diffusion。在示範資料豐富的任務上強。無校正迴圈。卡在示範收集瓶頸。
  • π0 / Physical Intelligence:VLA on millions of demonstrations。Demo 印象深刻。資本密集的資料收集。
  • Skild AI:robotics 基礎模型。$300M raised, pre-revenue。不同的 bet——示範規模。
  • 傳統 PLC(Siemens、Rockwell):人工調參,無學習。
  • Applied Intuition:自駕模擬。鄰近領域,不直接競爭。
  • LeWM / AMI Labs:pixel JEPA world models。不同的 stack 層級(perception);可以接在 Meadow 的上游。

Meadow 佔的是一個乾淨的空白:spec-driven、demo-light、calibration-native。

Q6

商業模式如何運作?

B2B,兩條收入流:

  • Per-deployment licensing——取代 2+ 週的整合商工程,且整合商成本顯著更高。Pricing 採詢價制。
  • 校正 SaaS——持續的本地漂移修正與策略 refresh。在客戶本地筆電上運作,不在我們的雲端;專有資料不離開客戶 perimeter——這對安全性敏感的產業移除了真實的採購阻礙。

Pilot 級經濟規模隨買方可衡量的付費意願(良率提升、停機減少)而 scale。具體數字在評估對話中、在適當保密層級下分享。
